# AI 记忆系统设计框架（助理型 Agent 的写入策略）

## 来源信息

- **类型**：设计框架笔记（理论 + 架构 + 实施策略，非代码）
- **本地路径**：`raw/notes/AI记忆系统设计框架.md`（124 行，2026-08-29 落盘）
- **目标形态**：长期服务单一用户的助理型 Agent
- **定位**：对本体系 [[../architecture/memory-stack]] 五层记忆栈的**理论对照面**——它回答「为什么记 / 记什么 / 何时忘」，本体系记录的是「记在哪 / 谁来写」

## 核心命题

**开放任务的开放性 = 任务描述与执行者所掌握上下文之差。**记忆系统的全部工作是把这个差缩小到「老朋友」水平——在系统内部把开放任务翻译成完全指定任务（"买杯咖啡" → 几点/哪家/什么/自取还是外卖）。

人并没有长上下文（工作记忆四五个块），人有的是**一条终身开放的写入通道**：经验持续被蒸馏进永久存储。LLM 的这条通道在训练结束那天焊死。所以问题不是「把一辈子塞进上下文窗口」，而是**学出一个好的写入策略**。

## 理论基础

1. **压缩必须先指定目标变量 Y**（率失真 / information bottleneck）。对助理 Agent，Y = "这个用户将来会需要我知道什么"，且 Y 在漂移。"完整记录"不是目标。
2. **两层依据**：**写入看惊讶**（相对当前用户模型可预测的不必存，信息量 = −log P）；**留存看效用**（写入时刻无法预知，必须事后靠实际使用做信用分配）。
3. **规则 + 例外表**（MDL 两部码）：高度重复的流坍缩为一条规则 + 偏差表，token 上极度有损、信息上近乎无损。规则是码本，偏差才是消息。
4. **遗忘是功能不是缺陷**：泛化要求丢弃细节；什么都留的完美日志反而让归纳更难。

### 生物记忆对照（作组织原则用，不作电路图用）

| 生物结构 | 角色 | AI 对应 |
|---|---|---|
| 皮层突触 | 终极长期仓库，写慢写稳 | 模型权重 |
| 皮层活动 | 工作记忆（活动态、挥发）+ 决策席 | 上下文窗口 |
| 海马体 | 归档员：一次性绑定何人何事何时何地，睡眠 replay 移交皮层 | **缺失**（记忆文件 / RAG 是不合格义肢） |
| 杏仁核 | 荧光笔：情绪显著性 → 放大写入增益 | **缺失**（Titans 惊讶门控抄此作业） |
| 基底节 / 小脑 | 程序性技能，重复 + 奖励刻入 | RLHF / 微调 / 固化策略 |

一句话：LLM 是「只有新皮层的系统」——缺海马体这支笔和杏仁核这只决定何时按笔的手。

## 四条设计不变量

- **I1 存索分离**：原始流水 append-only 永不销毁；一切"遗忘"实现为去索引和降权。压缩永远可反悔——这是机器对大脑唯一的结构性优势，整个框架建立在此之上。
- **I2 论证分离**：每条语义结论携带指向支撑情景的 provenance 指针（大脑有来源遗忘症，我们没必要有）。
- **I3 两道门分离**：惊讶决定写入（当场判），效用决定留存（事后判）。两判据两时刻不混用。
- **I4 读取即投票**：检索命中且被实际采用 = 强化信号；留存信用分配靠读取日志落地。

## 六模块架构

| 模块 | 生物类比 | 职责 | 笨版本（可先上） |
|---|---|---|---|
| 4.1 上下文装配器 | 前额叶 | 每轮在预算内装最小充分工作集：**语义优先、情景按需、原始仅审计**；兼判断"问还是拍板" | 固定 prompt 拼接 |
| 4.2 显著性门 | 杏仁核 | 内联轻量评估器打写入增益 γ；输入 = 预测误差 / 显式信号（**纠正是含金量最高事件**）/ 情感 / 结果意外度 / 出错代价。γ 只决定待遇不决定生死 | "用户说记住就记" |
| 4.3 情景库 | 海马体·编目 | 冷层原始转录 + 热层情景索引（按预测误差尖峰切事件 + 5W + 结果 + γ + 摘要 + 回指指针）；近期无条件保温 | append-only 日志 + 向量索引 |
| 4.4 巩固进程 | 海马体·移交 + 睡眠 | 离线 daemon 四职责：情节→语义蒸馏（规则+例外表）/ 一致性维护（矛盾按新证据改写、置信衰减）/ 留存信用分配（消费读取日志）/ **定期重压**（价值函数变了回原始流水重蒸馏，等于对自己的过去做 policy iteration） | 一段固定 prompt 的定时批任务 |
| 4.5 语义库 | 个体皮层 | 用户模型本体，条目 = 规则 + 例外表 + provenance + 证据数 + 置信 + 时间戳 + 状态；装配器主粮，必须小而精 | 带版本 KV |
| 4.6 程序库 | 基底节 | 存"顺手做什么"：输出格式习惯 / 工作流剧本 / 工具偏好 / 各域"问还是拍板"阈值；只由重复 + 结果反馈形成，单次陈述进不来；先显式 playbook 注入，终局蒸进 adapter 权重 | 一个偏好文件 |

**生命周期**：交互 → 门打 γ → 全量落冷层 / 热层按 γ 建索引 → 离线蒸馏进语义库/程序库（附 provenance）→ 装配器按需取用 → 读取日志回灌留存信用 → 周期性重压修正历史蒸馏。

## 刻意偏离生物设计三处

保留 provenance；去索引代替销毁；**支持真删除**（用户被遗忘权是唯一真烧磁带场景，须沿 provenance 图级联清除派生结论——provenance 本为可审计设计，顺手让诚实删除成为可能）。

## 实施策略与复杂度判断

- **架构不复杂、工程中等，复杂度藏在判断质量与评估回路**。在线路径 = 检索 + 装配 + 一次轻量打分，与常规 RAG 同量级；重活全在离线批处理，小模型即可；六模块中四个是普通软件，每个都有笨版本可渐进升级。
- **难点一：错误复利**。流水线由 LLM 判断串成，一条错误语义结论会被装配器反复注入，且"读取即投票"反向强化它。纠错机械（置信度 / 用户纠正高权重通道 / 沿 provenance 级联清除）工作量很可能超过主流水线。
- **难点二：评估回路极长**。"三个月后有没有想起该想起的事"无法单元测试。这是各家停在手写启发式的真实原因——不是学习型门控写不出，是缺耐心与信号去训。
- **关键不对称：记错比记不住伤害大得多。**路线 = 先用笨版本吃掉七八成价值，省下的力气砸纠错通道和评估，学习型部分留最后。
- 新增信任面：隐私、删除级联执行、记忆投毒（向长期记忆注入指令）。

## 现状对照与验收

碎片均已存在：Stanford generative agents（重要性打分 + 反思 ≈ 4.2 + 4.4 雏形）、MemGPT/Letta（4.1 + 4.3 分层）、Titans（惊讶门控进权重）。实践普遍缺四样：**I4 读取驱动留存 / 可反悔历史重压 / 学习型门控 / 整条程序通道**——几乎所有产品只做了陈述性记忆。

**咖啡测试**通过标准：提问率随相处时间单调下降，纠正后同类错误不再犯，且从不自信地记错。

## 与本体系对照（Hub 视角）

把六模块 / 四不变量套到 [[../architecture/memory-stack]] 五层栈 + Hub 工序上：

| 笔记模块 | 本体系现状 | 判定 |
|---|---|---|
| 语义库 4.5 | auto-memory `user_*` / `feedback_*`（带 **Why** ≈ provenance）+ 全局 CLAUDE.md 用户画像 | 有，但条目无置信 / 证据数 / 衰减字段 |
| 情景库 4.3 | session transcript（冷层，Claude Code 自管）+ `calendar/` 日志 + wiki `log.md`（热层雏形，按日期切、含摘要） | 部分——热层指针不回指 transcript |
| 程序库 4.6 | rules / skills / hooks / `feedback_*` 中的工作流类条目 | 有，且"只由重复形成"这条本体系反着做：单次纠正即写 feedback |
| 显著性门 4.2 | 笨版本：用户说"记住"/纠正 → feedback memory；`diff_memory_log.py` 的 promote-candidate 分类 | 笨版本到位 |
| 巩固进程 4.4 | 入会审计的 memory→wiki 蒸馏（08-18 首刀 memory 108→97，编年条 = "规则 + 例外表"的实例）+ CANON 级联 | 手动、非 daemon；有蒸馏无"重压" |
| 装配器 4.1 | SessionStart hook 注入 MEMORY.md 索引 + 三层渐进查询（index → log → ≤3 页） | 有；"语义优先情景按需"与 llm-wiki query 协议同构 |
| I1 存索分离 | `raw/` 只读 hook ✓；但 auto-memory 规则是"错了就删"，wiki 退役页也物理删 | **部分违反**——去索引优于删除，值得改 |
| I2 provenance | 一行 promote = 结论 + 来源 + 日期 ✓ | ✓ |
| I3 两道门 | 写入当场（session 内 memory）/ 留存事后（审计蒸馏） | 雏形 ✓ |
| I4 读取即投票 | **缺失**——审计十五~十七用 query/promote 计数做粗替身（"写多读少"诊断即此症） | ✗ 最大缺口 |

**可借鉴的两条**：① 把"读取即投票"落成最笨实现——query 命中 wiki 页时在页面 frontmatter 记 `last_used` / 计数，审计时用它裁 🕸️ 而非只看 mtime；② auto-memory 退役改"去索引"（移出 `MEMORY.md` 但文件留存）而非删除，对齐 I1。两条均属笨版本，工程量小，与笔记"先吃七八成价值"路线一致。
