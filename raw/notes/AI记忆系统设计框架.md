# AI 记忆系统设计框架

> 目标形态：长期服务单一用户的助理型 Agent。
> 核心命题：开放任务的开放性 = 任务描述与执行者所掌握上下文之差。记忆系统的全部工作，就是把这个差缩小到"老朋友"的水平——在系统内部把开放任务翻译成完全指定任务。

---

## 1. 问题定义

**开放任务 ≈ 封闭任务 + 一段看不见的规格化劳动。**"帮我买杯咖啡"之所以难，是因为把它翻译成"几点、哪家店、什么咖啡、自取还是外卖"的过程本身就是智能的核心：偏好推断、情境约束、例外长尾，以及判断哪些不确定性值得回来问、哪些自己拍板。熟人做得好，是因为他脑中有一个关于你的模型，默认值都能填得八九不离十。

**人类并没有"长上下文"。**人的工作记忆只有四五个"块"，数十年的经历也不以原始数据形式存在——原始转录早已销毁，留下的是被反复压缩归纳后的结论（偏好、习惯、图式、关于他人的模型）。人与 LLM 的真正差距不在"读"的容量，而在于人有一条终身开放的**写入通道**：经验持续被蒸馏进永久存储。LLM 的这条通道在训练结束那天就焊死了。

因此，问题的正确表述不是"把一辈子塞进上下文窗口"（不可能），而是"学出一个好的写入策略"（非常难，但可做）。人拥有的不是数十年的上下文，而是数十年的**固化过程**。

## 2. 理论基础

### 2.1 压缩的依据

"不遗漏信息"和"完整记录"都不是目标——在指定"为了什么"之前，压缩问题根本不成立。率失真理论和 information bottleneck 都要求先定义目标变量 Y。对助理型 Agent，Y = "这个用户将来会需要我知道什么"，且 Y 本身在漂移。

由此得到压缩的两层依据：

- **写入看惊讶**（相对于模型）：凡是当前用户模型能自己生成的，不必存——它已隐式存在于模型中。信息量 = -logP，完全可预测的事件信息量趋近于零。
- **留存看效用**（相对于未来）：写入时刻无法预知什么将来有用，因此留存判断必须事后做，靠实际使用做信用分配。

高度重复的流（"每天早饭吃什么"）应坍缩为**"一条规则 + 一张例外表"**（MDL 两部码）：在 token 上极度有损，在信息上近乎无损。规则是码本，偏差才是消息——"今天没吃早饭"只有衬在"天天喝粥"的背景上才携带信息。

**遗忘本身是功能，不是缺陷。**泛化要求丢弃细节；一个什么都留着的完美日志系统反而让归纳更难。AI 缺的不是更长的上下文，而是原则性的遗忘与抽象机制。

### 2.2 生物记忆的组织原则

| 生物结构 | 实际角色 | AI 对应 |
|---|---|---|
| 皮层突触（权重） | 终极长期仓库：写入极慢，写后极稳 | 模型权重（预训练 = 文明级蒸馏） |
| 皮层活动（前额叶领衔） | 工作记忆：持续放电的活动态，断电即失；兼决策席 | 上下文窗口（同样是运行态而非存储，同样挥发） |
| 海马体 | 归档员：一次性绑定"何人何事何时何地"，先自己垫存，再经睡眠 replay 移交皮层 | **缺失**——快速写入模块（记忆文件 / RAG 是不太合格的义肢） |
| 杏仁核 | 荧光笔：检测情绪显著性，放大当下的写入增益；是演化预装的写入价值函数，不做行动决策 | **缺失**——写入门控（Titans 以惊讶度门控即抄此作业） |
| 基底节 / 小脑 | 肌肉记忆：程序性技能，靠重复与奖励刻入，不经海马体归档 | RLHF / 微调塑造的行为倾向；反复执行后固化的策略 |

一句话：LLM 是"只有新皮层的系统"——有皮层的权重、有工作记忆的激活，缺海马体这支笔，和杏仁核这只决定何时按笔的手。

（边界说明：此为教科书级简化。真实记忆高度分布式，标准巩固理论与 multiple trace theory 仍有争议。当组织原则用很好，当精确电路图用会出错。）

## 3. 设计不变量

**I1 存索分离。**原始流水 append-only、永不销毁；一切"遗忘"实现为去索引和降权。压缩永远可反悔——这是机器对大脑唯一的结构性优势（大脑的压缩一次性、不可逆，磁带早已洗掉），整个框架建立在这条之上。写入时刻的无知问题由此从致命降为可恢复。

**I2 论证分离。**每条语义结论必须携带指向支撑情景的 provenance 指针。大脑有来源遗忘症，我们没必要有。

**I3 两道门分离。**惊讶决定写入（当场判），效用决定留存（事后判）。两个判据、两个时刻，不混用。

**I4 读取即投票。**检索命中且被实际采用，即是对该条目的强化信号——"用进废退"式的留存信用分配靠读取日志落地。

## 4. 系统架构：六个模块

### 4.1 上下文装配器（前额叶）

运行时组件，不是存储。每轮推理在预算内装配最小充分工作集：当前任务 + 语义条目（便宜，优先）+ 按需情景（要细节或出处时才拉）+ 激活的程序。纪律：**语义优先、情景按需、原始仅审计**——检索出二十段咖啡对话，不如一条"喜欢燕麦拿铁"。它同时是决策席：判断哪些不确定性值得回头问用户、哪些按记忆直接拍板。

### 4.2 显著性门（杏仁核）

交互中内联的轻量评估器，为每个时刻打写入增益 γ。输入：预测误差（对当前用户模型的惊讶度）、显式信号（"记住这个"；**纠正是含金量最高的事件**——惊讶、高未来效用、情绪充能三合一）、情感检测、任务结果意外度、出错代价。

γ 不决定生死，只决定待遇：高 γ 换来富索引、巩固优先级、直升语义库的插队权。因为原始流水都在（I1），此门可放心偏宽松——大脑门控失误是痕迹永久丢失，这里的失误只是浪费算力。先手写启发式，终局学出来（见 §6）。

### 4.3 情景库（海马体·编目岗）

两层结构。冷层：原始转录。热层：情景索引，每条 = 事件切分（按任务/话题转换点分段——人也是按预测误差尖峰切事件的）+ 何人何事何时何地 + 结果 + γ + 摘要 + 回指原文的指针。近期情景无条件保温（对应海马体的数月缓冲期），去留交给巩固进程。

### 4.4 巩固进程（海马体·移交岗 + 睡眠）

会话之间运行的离线 daemon，四项职责：

1. **情节→语义蒸馏**：聚类重复模式，坍缩成"规则 + 例外表"。单次高 γ 事件可直升语义库，但标低置信、待后续证据确认。
2. **一致性维护**：矛盾按新证据改写，保留版本痕迹；偏好会漂移，条目带时间戳与置信衰减。
3. **留存信用分配**：消费读取日志，被用过的强化，长期未读的去索引——不删（I1）。
4. **定期重压**：当价值函数变化（用户换了人生阶段，或门控策略升级），回到原始流水重新蒸馏历史。相当于对自己的过去做 policy iteration——大脑做不到。

### 4.5 语义库（个体皮层）

用户模型本体：稳定偏好、事实、关系、在做的事、图式。条目格式为"规则 + 例外表"，各带 provenance 指针、证据数、置信度、时间戳、状态（生效/被取代）。它回答"这个人是怎样的"；情景库回答"那天发生了什么"。这是装配器的主粮，必须小而精。

### 4.6 程序库（基底节）

存的不是"知道什么"而是"顺手做什么"：对该用户的输出格式习惯、工作流剧本、工具偏好、各领域的"问还是拍板"阈值。只由重复 + 结果反馈形成，单次陈述进不来。两个成熟度：先是显式 playbook（作为策略提示注入），最终蒸进 adapter 权重——到那步才是真基底节：不再"想起"，直接"就这么做"。

## 5. 一条记忆的生命周期

交互发生 → 显著性门打 γ → 全量落冷层，热层按 γ 建索引 → （离线）巩固进程聚类蒸馏，写入/更新语义库或程序库，附 provenance → （运行时）装配器按需取用 → 读取日志回灌留存信用 → 周期性重压修正历史蒸馏。

## 6. 终局问题：把写入策略学出来

门控与蒸馏器本质都是策略：动作 = {存 / 不存 / 怎么归纳}，奖励 = 数月后的下游效用（检索被采用、任务成功；用户对记忆的纠正记为负奖励）。跨月尺度的信用分配当然难——但原始流水在手（I1），它从"不可能"降级为"只是难"：可以反事实地重跑。

## 7. 刻意偏离生物设计的三处

1. **保留 provenance**（大脑有来源遗忘症）。
2. **去索引代替销毁**（大脑的遗忘不可反悔）。
3. **支持真删除**：用户行使被遗忘权是唯一真烧磁带的场景，且必须沿 provenance 图级联清除所有派生结论。副产品：provenance 本为可审计性设计，却顺手让诚实的删除成为可能——大脑连定向删除都做不到。

## 8. 实施策略与复杂度评估

**架构不复杂，工程中等，复杂度藏在判断质量与评估回路。**

- 在线路径只有"检索 + 装配 + 一次轻量打分"，与常规 RAG 同量级；模型本身无感。重活全在离线批处理，异步、可并行、小模型即可。
- 六模块中四个是普通软件（append-only 日志、向量索引、带版本 KV、定时批任务）。**每个模块都有笨版本**：门控可以先是"用户说记住就记"，程序库可以先是一个偏好文件，巩固可以先是一段固定 prompt。整套系统可从笨版本渐进升级，无任何部分要求一步到位。
- 真正的难点之一：**错误复利**。整条流水线由 LLM 判断串成，每步都可能安静地出错；一条错误语义结论会被装配器反复注入，而"读取即投票"会反向强化它。纠错机械（置信度、用户纠正的高权重通道、坏结论沿 provenance 级联清除）的工作量很可能超过主流水线。
- 真正的难点之二：**评估回路极长**。"三个月后有没有想起该想起的事"无法单元测试，A/B 一个季度才读得出数。这是各家停在手写启发式的真实原因——不是学习型门控写不出，是缺耐心与信号去训。
- 新增信任面：隐私、删除的级联执行、记忆投毒（向长期记忆注入指令）。

**关键不对称：记错比记不住伤害大得多。**一个自信地记错的助手，比一个失忆的助手更快失去用户。正确路线因此沿复杂度梯度走：先用笨版本吃掉七八成价值，把省下的力气砸在纠错通道和评估上，学习型部分留到最后。

## 9. 现状对照

碎片均已存在：Stanford generative agents 的重要性打分 + 反思 ≈ 模块 4.2 + 4.4 雏形；MemGPT/Letta 做了 4.1 + 4.3 的分层；Titans 把惊讶门控做进权重；各家助手产品跑着 4.4 的手写简化版。

实践普遍缺四样：读取驱动的留存信用分配（I4）、可反悔的历史重压（4.4-d）、学习型门控（§6）、整条程序通道（4.6）——几乎所有产品只做了陈述性记忆。

## 10. 验收标准（咖啡测试）

当"帮我买杯咖啡"进来时：装配器从语义库拉出口味，从程序库拉出"这类小事他嫌问多"，从情景库确认上次那家踩过雷——在系统内部把开放任务翻译成完全指定任务，且知道剩余哪个不确定性（如果有）才值得占用一次提问。

通过标准不是"记住了多少"，而是：**提问率随相处时间单调下降，纠正后同类错误不再犯，且从不自信地记错。**
